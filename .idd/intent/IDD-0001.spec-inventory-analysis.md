# IDD-0001.spec-inventory-analysis

## Behavior
InventoryPulse produces a reproducible daily analytical excess and obsolete (E&O) position from enterprise records. Four bounded cooperating agents retrieve source-referenced data, reconcile SKU identities, calculate E&O, and rank explainable disposition proposals. Every hand-off is validated and contains run ID, cutoff, agent identity, versions, status, confidence, source references and exception flags. Incomplete, stale, ambiguous and future records are quarantined rather than accepted silently.

An explicit versioned policy defines demand horizon, safety stock, aging and recovery economics. Excess equals nonnegative on-hand minus policy target; obsolete inventory is classified separately without double counting. Positions consolidate quantities only across unique source/warehouse records representing separate physical holdings. Unit costs and demand inputs must agree across matched holdings; conflicts require review. Open purchases are reported separately from current on-hand exposure.

SKU matching combines normalized identifiers and description similarity, abstaining on ambiguous candidates. Precision and recall use labelled examples including expected unmatched cases. A versioned crosswalk records accepted and rejected decisions. Monthly reconciliation requires identical scope and cutoff, includes missing SKUs, absolute and signed variances, and undefined percentages when the baseline is zero.

Recommendations rank feasible mutually exclusive options per SKU with quantity, recovery assumptions, costs, estimated net recovery and approval state. No option executes an ERP action. A durable human decision log records approval or rejection of one option per SKU; concurrent or repeated decisions cannot double count opportunity. Approval does not imply execution or realized cash. Weekly summaries are role-tailored and threshold breaches are exported for business delivery.

Microsoft Agent Framework coordinates four separate tool-calling model agents in a typed sequential graph. Each agent must invoke its bounded stage tool, cite available evidence and acknowledge its exact receipt before the next stage runs. Invalid model output, fabricated receipts or out-of-scope citations stop execution. Model-proposed SKU matches remain human-reviewed suggestions and cannot override deterministic identities. Data review requests stop the graph; completed proposals await a separate human approval gate. Fabric mode retrieves only via a published Data Agent MCP endpoint and never falls back silently to sample data. Framework tests with simulated model responses must be labelled as such, distinct from live tenant evidence.

## Acceptance criteria
- An end-to-end synthetic scenario produces positions, crosswalk, scorecard, exceptions, reconciliation, recommendations, role reports and audit events, each tied to a reproducible run and source fingerprints.
- Invalid values, ambiguous identities, duplicate holdings, inconsistent costs/demand and stale/future feeds cannot silently affect financial outputs.
- Financial arithmetic is deterministic, nonnegative, rounded in decimal currency; alternate recommendations never add together as independent release.
- Monthly reconciliation refuses unequal cutoffs and documents missing/extra rows.
- Human decisions persist, identify the reviewer, enforce one final decision per SKU, and leave realized cash zero.
- Local dashboard clearly labels synthetic data and cloud deployment status.
- Fabric deployment supports curated Delta tables and published Data Agent MCP retrieval; Microsoft Agent Framework orchestration with Foundry/Azure OpenAI models, separate Entra identities, Agent 365 audit, Power BI, Activator and Teams require live tenant evidence before being described as deployed.

## Constraints
Synthetic data contains no client records. A local demonstrator is not a production service. No unattended ERP writes, invented savings, unproven cloud governance claims, or autonomous physical counting. Tenant features, legacy business policy and disposition economics remain deployment prerequisites; sample policy is explicitly illustrative.

## Verification
Exercise a representative synthetic end-to-end run, precision/recall against labelled matches, same-cutoff reconciliation, invalid-input quarantine, overlapping-option financial aggregation, durable approval and duplicate-decision protection. In a licensed tenant, separately demonstrate live MCP grounding, four-agent orchestration, identity/audit scope and each delivery channel.
