# Изолированные агенты: проверка обобщения

2026-11-07, настоящая локальная Ollama, `gpt-oss:latest` (20.9B, MXFP4). Модель не обучалась и её веса не менялись. Проверялось возможное переобучение промптов на демонстрационные примеры, а не fine-tuning.

## Процедура

1. До контрольных запросов зафиксированы сценарии, ожидаемые решения и исходные данные. Development и holdout используют разные вымышленные товары, поставщиков, MPN, SKU, описания, даты, цены и объёмы: три складские записи в development, пять в holdout.
2. По каждому агенту выполнялся отдельный Microsoft Agent Framework workflow с одним настоящим LLM-агентом. Предшествующие стадии выполнялись только детерминированными инструментами. Ответы других моделей не передавались как входы.
3. На development допускаются правки; ожидаемые ответы не входят в запрос к модели. После правок — десять отдельных повторных прогонов.
4. Перед holdout записаны хеши кода и промптов. Источники не менялись до конца обоих контрольных прогонов. Запуск повторного holdout тем же скриптом запрещён маркером открытия. Правки под контрольные ответы не делались.
5. Сравнивались пары с одним изменённым условием: корректная/некорректная дата, нулевая/ненулевая сверка, pending/самосогласованное предложение. Отдельно проверялось сохранение решения при переименовании кодов и перестановке строк.
6. Для извлечения документов подготовлен отдельный holdout с другими компаниями, переставленными столбцами, иными названиями полей, GBP/USD/AUD, неизвестной единицей поставки, отсутствующим MPN и внедрённой инструкцией. В prompt нет конкретных компаний, SKU или ответов из этих наборов.

Скрипты: `scripts/agent_generalization_experiment.py`, `scripts/document_generalization_experiment.py`. Протоколы и данные сохраняются до запросов. Для полного повторения нужен новый output/fixtures каталог; старый контрольный набор остаётся раскрытым.

## Изменения по development

Исходная конфигурация прошла 4/10 development-проверок. Ответы смешивали обязанности ролей: появлялись неподтверждённые сопоставления и поля другой роли. Расчётный агент разрешал продолжить без обязательной сопоставимости месячной сверки. После первого исправления прошли 9/10 проверок: последняя ошибка была противоречием `reason_code=ready_for_approval` и `disposition=request_review`.

Теперь у каждой роли ответ LLM состоит из **двух строковых полей**: `reason_code` и `rationale`. Продолжение/остановку приложение выводит из кода причины и проверяет по фактам инструмента. Хеши, ссылки, массивы и финансовые расчёты не генерируются моделью. Это устраняет противоречивое дублирование статуса, а не добавляет частные исключения для тестовых товаров.

Промпты выражают общие границы ролей: не придумывать идентичности, не подменять сверку актуальностью текущего расчёта, не считать ожидаемый эффект реализованными деньгами, не одобрять собственные предложения. Из промпта извлечения удалены конкретное имя Generic (synthetic) и частные примеры единиц: остаётся требование сохранять полное исходное значение, не сокращать квалификаторы и брать единицу из поля поставки, а не из основания цены.

## Закрытый контроль — первый проход

| Агент | Проверки | Результат |
| --- | --- | --- |
| Retrieval | Чистые данные, частичные исключения, отсутствие пригодных строк, переименование/порядок | 4/4 |
| SKU Matching | Разрешённые идентичности, неизвестное исполнение, переименование/порядок | 3/3 |
| E&O Calculation | Полное согласие, другая дата baseline, ненулевая разница, переименование/порядок | 4/4 |
| Recommendation | Pending-предложения, уже одобренные предложения, реализованная сумма до исполнения, переименование/порядок | 4/4 |
| Подготовительное извлечение документов | Новый порядок столбцов, новые названия полей, иной формат предложения и инструкция внутри документа | **2/3** |

Итого по четырём агентам: **15/15**. По дополнительному извлечению документов: **2/3**. Оба файла `freeze-integrity.json` подтверждают неизменность тестируемого кода.

### Открытая ошибка обобщения

В документе `reordered_table` модель вернула `Orbit Calibration Ltd` вместо `Orbit Calibration Ltd [West]`. Остальные проверяемые поля двух позиций извлечены верно, но удаление уточнения поставщика может нарушить соединение с учётными данными. Проверка зафиксирована как провал, а не переименована в успех. Промпт после раскрытия этого примера не менялся. Исправление следует проверять на новом независимом наборе с другими квалификаторами, не на этом же примере.

## Что результат доказывает и чего не доказывает

Подтверждены отдельные tool-calling вызовы и решения LLM-ревьюеров по ограниченным фактам в новых синтетических условиях. Неподтверждённые решения блокируются приложением. Доменные сопоставления и денежные расчёты выполняют инструменты; это не измерение качества самостоятельного поиска SKU или арифметики LLM.

Конечный небольшой holdout не доказывает отсутствие переобучения во всех будущих распределениях. Схема ответа, промпты и представление фактов менялись вместе; рост результата нельзя приписывать исключительно формулировке промпта. Смена языка, большие каталоги, другие виды источников и реальные операционные данные требуют дополнительных независимых проверок. Наличие выявленной ошибки извлечения — ограничение обобщения, а не основание объявить систему универсальной. Fabric, Entra и Agent 365 здесь не испытывались.
