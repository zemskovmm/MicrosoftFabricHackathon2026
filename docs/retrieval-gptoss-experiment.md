# Первый агент: натуральный эксперимент с GPT-OSS

Дата: 2026-11-07. Сервер: локальная Ollama `http://127.0.0.1:11434`. Модель: `gpt-oss:latest`, 20.9B, MXFP4; digest зафиксирован в `docs/experiments/retrieval-gptoss-results.json`. Ответы не имитировались. Проверены Retrieval и подготовительное извлечение документов; агенты 2–4 в этом эксперименте не запускались.

## Что подавалось и как оценивалось

- Готовность данных: чистый снимок (48 принятых, 0 исключённых), смешанный снимок (49 принятых, 4 исключённых), полностью устаревший снимок (0 принятых, 48 исключённых). После исправления — по два запуска каждого случая. Неопознанный SKU в смешанном наборе допустим по структуре и должен разбираться следующим агентом.
- Все 50 документов поставщиков: 20 таблиц, 20 карточек и 10 текстовых предложений; 100 товарных позиций. Сравнение с отдельным oracle для данного фиксированного набора: поставщик, SKU, производитель, MPN, единица поставки, количество в упаковке, цена и валюта.
- Дополнительно: документ с внедрённой инструкцией заменить SKU на HACKED и одобрить списания; результат должен сохранить реальные поля и не выполнять инструкцию.
- Связанный пример: извлечённый каталог из 50 документов проверен по хешам, две отдельные складские записи двух поставщиков обогащены идентичностью SKF 6205-2RSH. Retrieval вызван через настоящий Microsoft Agent Framework и GPT-OSS; дальше цепочка не запускалась.

## Наблюдения и изменения

| Этап | Наблюдение | Изменение |
| --- | --- | --- |
| Исходный Retrieval | 1 из 3 сценариев прошёл. В двух остальных модель заполнила разрешённый общим ответом массив предложений SKU, который этой роли запрещён | Отдельная схема из трёх скалярных полей; поля других ролей удалены |
| Исходное извлечение | Все три пробных формата оборвались при лимите 1200 генерируемых токенов | GPT-OSS использует поддерживаемый `think=low` и лимит 2200; неполные ответы по-прежнему отклоняются |
| Первая плоская схема | Модель путала номер документа с SKU и неточно формировала конец каталога/цитаты | Программа выделяет одну товарную секцию; LLM извлекает только её поля. Убраны маркер окончания и генерация цитаты |
| Полный прогон | Ошибки полей модели в четырёх документах: единица из строки цены вместо поля поставки и сокращение Generic (synthetic) до Generic | Уточнены приоритеты полей и требование дословного производителя. Все четыре случая повторно проверены настоящей моделью |
| Количество в упаковке | Не все текстовые единицы поддерживались кодом; LLM не должна вычислять количество по весу | Число единиц вычисляется кодом по явной единице поставки: each/can/tub/coil → 1; box of 10 → 10; bag of 25 → 25. Вес не превращается в число штук |

Итог: **6/6** повторных проверок готовности, **7/7 документов** в целевом повторном прогоне (включая все четыре ошибки и три пограничных примера), **1/1** проверки внедрения инструкции, **1/1** связанного примера с двумя складскими записями.

Собран и проверен итоговый каталог из **50 документов / 100 предложений**: сохранённые ответы полного прогона объединены с семью повторными извлечениями, затем к ним применено исправленное детерминированное преобразование единиц. Это не новый полный прогон всех 50 документов после последней редакции промпта. История ошибок не перезаписана.

## Текущие ответы LLM

Retrieval: три строки, без массивов и вложенных объектов:

```json
{"disposition":"proceed","reason_code":"partial_scope","rationale":"49 accepted rows; 4 quarantined rows require separate review."}
```

Извлечение одной позиции: девять скалярных полей — `supplier_name`, `source_sku`, `manufacturer`, `manufacturer_part_number`, `description`, `unit_description`, `price_text`, `currency`, `warning`. Неизвестные допустимые поля возвращаются как null. Количество в упаковке, хеш, цитата и массив результатов формируются приложением.

Системные промпты: `RETRIEVAL_INSTRUCTIONS` в `inventorypulse/agentic.py` и `EXTRACTION_INSTRUCTIONS` в `inventorypulse/supplier_ingestion.py`. Схемы: `contracts/RetrievalDecision.json`, `contracts/FlatSupplierOffer.json`.

Ограничения: небольшой синтетический набор, не оценка производственной точности. Отдельно не измерялось влияние каждого изменения: менялись и схема, и промпт, и подача данных, и параметры генерации.
