# Fabric deployment runbook

These are deployment assets, not proof of a deployed tenant. Requires licensed Fabric capacity, a dedicated Lakehouse with contributor access, Azure OpenAI/Foundry model access, Entra Agent ID and Agent 365 tenant capabilities. Do not provision paid capacity implicitly.

1. Build the wheel: `python -m pip wheel --no-deps . -w output/wheels`. Upload it as a Fabric Environment custom library and attach the published environment to a Spark notebook. Attach the dedicated default Lakehouse. This manual step avoids undocumented deployment APIs.
2. Upload `data/sample` to Lakehouse `Files/inventorypulse/input`. The notebook can ingest those synthetic files; change `AS_OF` only when input snapshots and baseline align. Import `inventorypulse.ipynb`. Run it once, inspect exceptions and counts, then schedule daily only after the real feed policy is agreed. Source fingerprints and policy versions make reruns traceable.
3. Create and publish a Fabric Data Agent grounded only on approved source tables (exclude `source_labels` and other offline evaluation data). Give it the bounded retrieval instructions from `agents/roles.json`. Record the real workspace and data agent IDs, and copy the MCP URL from its settings. The supplied `fabric-fetch` CLI performs the official streamable HTTP handshake with an Entra token. Validate returned row counts and financial totals against SQL before using LLM-shaped retrieval; structural validation alone does not prove completeness. Use deterministic Lakehouse ingestion for production-scale data.
4. Import `agentic.ipynb` and attach the same Lakehouse plus a Fabric Environment containing the wheel and its `agentic` dependencies. Configure the Azure OpenAI endpoint/deployment and approved Entra credentials. This notebook runs the four-agent Microsoft Agent Framework graph, retrieves through the published Fabric Data Agent MCP endpoint, and exports outcome, receipts and hand-offs. It creates no cloud identities or model deployments. See `docs/agent-framework-handoff.md`.
5. Build a Power BI semantic model from `positions`, `recommendations`, `run_summary`, `exceptions`, `reconciliation` and `decisions`. Require a single selected run via `run_summary[run_id]`; create one-to-many relationships from run_summary to each fact. Convert currency strings to fixed-decimal/currency and quantities to decimals. Use `powerbi.dax` measures; proposals must not be summed across ranks. Add risk/age, exceptions, matching quality, monthly variance and approval views. Keep realized cash zero until a separately governed execution feed exists. Local decisions are not synced automatically: export them from the dashboard API/store after review and ingest with run_id and estimated_release.
6. In Fabric Activator configure a rule on `run_summary.eo_value > run_summary.alert_threshold`, grouped by `run_id`. Use the explicit `alerts` table to inspect which runs breached. Add a real Teams notification action to the intended audience and capture the triggered notification. An exported alert row is not evidence of live Activator delivery.
7. Create Teams Workflows that accept Adaptive Card webhook requests, one per approved audience. `inventorypulse.delivery.send_teams_report` builds and sends the card only when explicitly called. Keep workflow URLs in approved secret storage. Schedule weekly delivery after recipient authorization; no messages are sent by the daily engine. Reports summarize the latest daily snapshot, not weekly aggregates.
8. Register one Entra Agent ID per cloud agent; enforce retrieval read-only access and limited results writes. Validate each identity cannot exceed its intended scope, enable Agent 365 audit, and save real traces. A local SQLite hash chain is not a substitute.

## Readiness gates

Do not mark cloud items complete until live MCP, grounded row counts, orchestration, identity access tests, Agent 365 traces, Power BI refresh, Activator notification and Teams delivery are captured. Confirm real legacy E&O rules, demand horizons, scope ownership, FX/currency, supplier return terms, inter-site demand and authenticated approval owners before replacing illustrative policy.
